## The archive

A ZIP, DEFLATE, **backslash** entry names (`Localization\en-US.dat`; Python's
`zipfile` on Windows hides this by showing `/`). Order as the product writes it:

```
Bindings.dat                 JSON  Sources -> Bindings -> Targets
CompoundObject.objdef        JSON  identity
CompoundObjectSettings.dat   JSON  {Type:"CompoundObjectSettings", UniqueId, Name, ConfirmPasswordOnExport?}
Converters.db                SQLite  Scale / Expression converters (same schema as a project's)
LocalVariables.db            SQLite  the object's own variables ($Local.X); absent in one sample
Properties.propDef           JSON  the exposed properties
Resources.dat                JSON  {} in every sample
Screen.dat                   JSON  the object's tree
Script.dat                   JSON  Blockly-style scripts (4.0 samples only)
Validations.db               SQLite  (4.4 samples only)
Localization\<locale>.dat    JSON  ten locales: de-DE en-US es-ES fr-FR it-IT ja-JP ko-KR pt-BR zh-CHS zh-CHT
_metadata                    JSON  {EncryptionInfo, SignatureInfo, AdditionalMetadata, Hint}
```

JSON formatting the product uses (it accepts other formatting, but an edit
should not reformat): objdef, Bindings and propDef indented two spaces with
CRLF; Screen.dat and the settings on one line; localization indented with LF.
The SQLite files are in WAL mode (header bytes 18 and 19 are 2).

A library package (`COs.pkg`) is a ZIP of `<Id>.co` entries and `Hierarchy.dat`,
a folder tree `[{Id, Name, Type:"Folder", Children:[{Id, Type:"CompoundObject"}]}]`.

## Identity

`CompoundObject.objdef`: `Name`, `Id` (lower-case GUID), `LayoutType` (0 = the
tree is a Grid, 8 = a ViewBox that scales), `ModifiedAppVersion`, `AppBrand`
(Schneider or Pro-face), `ScriptMode` (0), `ErrorLevel`, `CreatedDate`,
`ModifiedDate`, `CommitId`.

Invariants, true in all 38:

- `Screen.dat` root is `{Type: "CompoundObject", SubType: Name, Name: Name, UniqueId: Id}`.
- Every Source with `ObjectType 16` has `ObjectId` = Id (upper case) and `SubType` = Name.
- Every binding's `Target` and each id in its `Sources` exist.
- Every part a Target names (`ObjectType 8`) is in the tree.

**What the licensed editor changes on import** (our `HMICopilot_PumpSpeed.co`
against its copy): nothing but identity and stamp. The name was taken, so it
became `HMICopilot_PumpSpeed1` with a new Id, rewritten in objdef, the
Screen.dat root, every type-16 Source (`ObjectId`, `SubType`) and every part
Target's `ParentIds` and `ScreenId`; `ModifiedAppVersion`, `ModifiedDate` and
`CommitId` were restamped. Every other entry came back byte-identical.
`renameCo` reproduces those rewrites exactly (5/5 entries equal, ignoring the
stamp).

## Exposed properties

`Properties.propDef` is a JSON array:

```json
{ "Id": "<guid>", "PropertyName": "CurrentValue", "PropertyType": "Double",
  "DefaultValue": 0.0, "FirstLevelCategory": "Function", "SecondLevelCategory": "Basic",
  "BindingMetadata": { "AllowedValueType": "Alarm, Variable, ..., Constant", ... },
  "SupportedBindingSources": "CompoundObject, defaultWithLocalVariable",
  "ValidationInfo": [ {"Type": "Required"}, {"Type": "Range", "Parameters": {"Min": {"Value": 0}, "Max": {"Value": 99}}} ],
  "ListStartIndex": 0 }
```

- `Struct` groups children (`Colors.ForegroundFill`); the path is the dotted names.
- Types seen: Double, Int32, Boolean, String, Brush, Brush_NoneSolidBlink, Color, FontNameList, Struct.
- A constant-only property (a range end) has `WriteMode: "Constant"`, `SupportedBindingMode: "OneWay"`, `AllowedValueType: "Constant"`.
- Brush and Color properties have `WriteMode/SupportedBindingMode: "None"`; brushes use `PresentationType: "FillBrushDisplay"`.
- Display names and descriptions live in `Localization\en-US.dat` under `PropertiesLocalizationInfo[{PropertyId, Name, Description}]`.
- **The values a definition carries are keys on the Screen.dat root**, at the property path: `{"CurrentValue": 65, "Colors": {"ForegroundFill": {...}}}`.

## How properties drive the parts: Bindings.dat

```
Sources[]   {ObjectType, ReferenceId, ObjectId, SubType?, ParentIds?, ScreenId?, ObjectFullName, PropertyFullName?}
Targets[]   {ObjectType, SubType, ReferenceId, ObjectId, ParentIds?, ScreenId?, ObjectFullName}
Bindings[]  {Type, Mode, BindingText, ConverterId, ConverterName, Target: <ref>, TargetProperty, Sources: "<ref>[,<ref>]"}
```

| Code | Source | Target |
|---|---|---|
| ObjectType 16 | an exposed property: ObjectFullName `CompoundObject`, PropertyFullName = path | |
| ObjectType 6 | a local variable | a local variable |
| ObjectType 8 | a part | a part; SubType = its Type |
| ObjectType 19 | | a converter: SubType `Scale` or `Expression` |
| ObjectType 100 | | a script block input: `Value.ScreenObject`, `Value.LocalVariable` |
| Binding Type 15 | BindingText `$CO.<path>` | |
| Binding Type 9 | BindingText `$Local.<name>` | |
| Mode | 2 for numbers and values driven live, 1 for brushes, colours, text and converter ends | |

Patterns, all from the samples:

- **A value through a range**: `$CO.CurrentValue` → part property (`Animation.FillLevel.VerticalFill`, `EndAngle`) with `ConverterId/Name` of a Scale row in Converters.db, and `$CO.Min` / `$CO.Max` → that converter's Target (`ObjectType 19`) as `FromMin` / `FromMax`. Converter rows are `{UniqueId (upper), Name, Order, ConverterType: "Scale", Description: "", Data: JSON}`.
- **A brush or colour**: TargetProperty `<prop>.@StructBindingValue` (`Fill.@StructBindingValue`, `Animation.FillLevel.BackColor.@StructBindingValue`), and the part holds `"@StructBindingValue": null` at that path.
- **An expression**: a converter of SubType `Expression` whose BindingText is a formula, `([FromData]-$CO.Range.Min)*100/($CO.Range.Max-$CO.Range.Min)`.
- **State logic** (Pro-face lamps and switches): properties feed `Script.dat` blocks (Trigger Condition / Touch / ValueChange), the scripts write local variables (`ColorVisibility[0..8]`), and those drive part visibility. A lamp's colour is a script, not a binding.

## Building one from nothing

`buildCo(spec)` (`hmi co build spec.json -o out.co`) writes every entry above
from a description: parts, exposed properties with types, ranges, labels and
values, wires from property to part property, and Scale converters. It creates
the SQLite files empty with the product's own schemas, puts each converter in
Converters.db, adds the `@StructBindingValue` slots, and reads its output back
before returning. `demo_objects/specs/HMICopilot_LevelTile.json` →
`demo_objects/HMICopilot_LevelTile.co` is the first one: a label, a level bar
through `Scale_to_0_100`, and the reading.
